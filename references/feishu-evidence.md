# 飞书证据映射

从飞书数据资产里**只读**梳理行为证据，映射到双模型的六个维度。飞书是主要诊断依据，但读取遵循「先确认身份 → 只读 → 脱敏 → 用户授权/对本人透明」。外部系统 ID、租户、凭证由运行环境提供，Skill 不保存令牌。

## 身份核验（读取前必做）

```bash
lark-cli auth status --json --verify
```

确认 `identity=user`、`verified=true`。他评模式下，使用者须是该成员的直接管理者，且过程对本人透明。

## 数据源与命令

| 资产 | 命令示例 | 主要支撑的维度 |
| --- | --- | --- |
| OKR | `lark-cli okr +cycle-detail --as user` | 成就（目标是否拉伸）、权力（跨团队推动）、自主（是否自主设定） |
| 文档 | `lark-cli docs ...`（用户指定文档） | 成就（深度钻研）、自主（主动发起）、胜任（成长曲线） |
| 周会/会议 | `lark-cli minutes ...` / `calendar +agenda` | 亲和（协作）、权力（主导议题）、归属 |
| 员工与 Agent 的交流 | 会话导出 / 用户提供（codex / claude / 豆包企业版等） | 成就（钻研难题）、自主（主动探索）、胜任（学新技能）、权力（规划影响） |
| 对话消息（辅助） | `lark-cli im ...`（仅辅助，他评须透明） | 亲和、归属 |

**员工与 Agent 的交流内容**是这枚 Skill 的一个特色信号源：一个人和 AI 怎么对话——追问到底还是浅尝辄止、主动探索还是只等指令、钻研什么——很能反映其驱动。它是 agent-agnostic 的，任何 Agent 的会话导出都可纳入。自测模式下用本人自己的会话；他评模式下须对本人透明。

具体维度信号见 [motivation-model.json](motivation-model.json) 里每个维度的 `feishu_signals`。

## 证据 → 结论的支撑逻辑

每条诊断结论必须能回溯到具体证据，格式：

```
维度：倾向（强/中/弱）
  ├─ 支撑证据：<来自哪个资产的哪条具体行为>
  ├─ 推断逻辑：<为什么这条证据指向这个维度>
  └─ 置信度：<高/中/低> —— 行为推断，与本人认知可能有差
```

## 边界

- **消息类证据只作辅助**，且他评模式下必须对本人透明；绝不做背后扒消息下结论。
- 主依据用工作产出类资产（OKR/文档/周会/与 Agent 的交流），边界清晰。
- 只读、脱敏；不把敏感个人信息（薪酬历史、健康、家庭等）纳入证据。
- 证据不足的维度，标注「证据不足」，不硬给倾向。
- 读取只服务于发展性诊断，不用于考核、排序或背对背评估。
